# OpenRig v0.5.14 — clearer navigation, mission progress and human notifications

OpenRig 0.5.14 makes reading more predictable when opened or refreshed, keeps
human requests distinct from informational updates, and groups instance settings
and health where they are easier to find.

## Enter and keep reading

Bare interactive `rig` enters the ordinary TUI after confirming a running rig.
An instance without running rigs keeps the startup chooser. Help, Skip and Local
remain responsive during slow or unverified detection; a late observation does
not take navigation away after the user has chosen another route.

Pages distinguish initial loading, successful empty results, refresh and failure.
The navigator remains usable through page and rig changes. A previously read page
can stay visible with its original scope label while the selected page loads;
that prior content has no action targets. Same-scope refresh retains useful content,
with the previous read time and Retry. A failed Feed source retains its own data
while healthy sibling sources update. Confirmed denial, empty results and removals
clear affected content, and late replies cannot replace the current selection.
First visits retain navigation and local feedback. Topology first offers rig
selection, then reads that rig before unrelated fleet details. Terminal names are
available before detailed readiness and preview.

Projects keeps malformed mission and slice sources visible as local errors while
healthy neighbors remain readable. Correcting the affected source and refreshing
restores its content without showing its parser fragment above unrelated work.

Optional blocker descriptions load independently, so an unavailable description
does not hide primary queue facts or change the recorded human recipient.
Fleet reads share one elapsed request budget across stages and retain local
results when a remote source fails. Repeated proof-policy and delivery-receipt
reads avoid duplicate work while later reads still observe current inputs.
These changes reduce measured work; they do not establish a latency guarantee.

Selective restore and startup event indexes reduce inventory read work while
preserving event history and projection results. Private query replay does not
establish a general live response-time guarantee.

Terminal catalogs reuse one inventory read instead of repeating the same global
scan. The measured result was equivalent with less query work; this is not a
general latency guarantee. Existing saved-view discovery, passive preview and
deliberate Herdr Open remain available.

## Complete requests and quiet updates

Human notifications distinguish explicit decision requests from informational
updates. A request carries a complete brief and requested action; related
supplemental detail can continue in its thread. Content that exceeds supported
limits is refused with an author correction instead of silently losing essential
text. The shipped authoring guidance calls for concise, complete human briefs.

Informational FYIs require no action or reply and do not create approval
obligations. Delivery completion is separate from a human decision. Partial or
ambiguous delivery remains distinguishable, and retry/reply tracking keeps each
request and its thread separate. Existing callers without an explicit intent
retain decision behavior.

## Find requests and instance health

The six top-level entries are **Topology, Specs, Projects, Terminals, Feed and
System**. Feed explicitly covers the instance and all humans. **Human requests**
shows recipients and relevant scope; **Updates** includes confirmed delivered
FYIs alongside existing outcome and health updates. Delivered FYIs remain in a
bounded history after their delivery obligation closes. Reading is not approval.
Feed's Explorer contains these categories, with entries in the content pane.
Specs kind groups and Derived terminal views start collapsed and expand explicitly;
Saved views stay prominent. Saved membership still requires deliberate setup, and
opening a terminal view remains an explicit action.

System opens to instance **Health**, followed by **Configuration** and
**Connections**. Contextual Health, global Help and compatible direct commands
remain available, including `attention`, `needs`, `feed`, `config` and
`connections`.

## Understand mission progress

Projects puts completed outcomes, current work and owner, blockers, next dependency
and slice boxes before process prose at both terminal widths. Accepted required
proof judgments determine slice outcomes; all slice outcomes must be complete
before the mission reports outcomes complete. Evidence attachments, quiet activity
and handoff alone do not accept proof. Reopened or assigned unfinished work stays
open, including when there is no unassigned next slice.

Actual custody and planned ownership remain separate. Authored lifecycle and
publication are separate from outcome completion; unknown ownership or eligibility
stays unknown. Narrow screens retain a full first box and scroll for the remainder.

## Operator notes and verification limits

Root, CLI, daemon and web UI versions are 0.5.14; the terminal TUI remains 0.1.0.
Node requirements are unchanged. Migration 081 adds explicit intent and
supplemental detail to queue records. The migration head is now
`084_inventory_event_indexes`, adding three selective inventory read indexes;
083 adds the two review read indexes. Migration 082 adds nullable identity
provenance to archived queue transitions. Archival preserves recorded values and
refuses an archive schema that cannot carry them; legacy unknown values remain null.
Shared history, RECENT and OWNER/receipt readers now include archived records,
so their results can broaden even where the command or TUI code is unchanged.
Migration alone does not reconstruct previously lost metadata. Use the supported
upgrade and continuity process when adoption is authorized.

The private combined review exercised installed journeys at 140×42 and 80×24,
including entry, refresh, source failure, scope identity, detail/Back, saved
terminal Open and notification correlation. An initial Feed source-failure defect
was retained in the evidence and repaired, then independently rechecked. Owner
candidate-native evidence and the reviewer's child TUI against an unchanged
parent daemon remain separate observations.

Later operator inspection exposed disruptive navigation and a misleading mission
overview. The corrected private combined review covers the new navigation,
organizers and native mission states. Its false NEXT-completion finding was
preserved, repaired and independently rechecked at both widths. These private
results remain limited to the journeys and environments exercised.

VM inspection was accepted on September 14: generally zero-to-two-second
loading with occasional timeouts, along with formatting, icon colors and default
views. This observed result is not a general latency or availability guarantee.
Later recovery of the same candidate preserved sessions but did not establish a
durable responsiveness fix.

- Intermittent read timeouts remain. An inherited CLI health-check deadline can
  report the daemon unresponsive before sending a queue request even when the
  direct request succeeds. That defect is not fixed here; occasional server
  delay also remains unattributed.
- Earlier notification checks used controlled HTTP responses and synthetic replies.
  A later real single-consumer Slack exercise confirmed complete decision/detail/FYI
  posting and reply correlation; the operator confirmed phone readership and
  readability. That observation does not establish OS push behavior or all clients.
- Terminal provider evidence covers disposable Herdr members. Other provider,
  remote and parent-host behavior is not established by this review.
- Saved Build watch discovery was exercised in the VM and its native judgment
  recorded. That observation does not establish general navigation responsiveness.
- Simultaneous default TUI clients retain the existing programmatic control-socket
  limitation. Unique test sockets do not prove general multi-client isolation.
- Version and package checks do not repeat the development journeys or establish
  a new whole-source, all-platform or unfamiliar-human usability result.
- Observed shutdown-drain timeouts, recorded config-preservation uncertainties
  and a prior `recorder_write_failed` observation are not claimed resolved.
  Recovery evidence remains distinct from ordinary-entry verification and does
  not establish whole-system health.
- Historical source-scan findings retain their recorded dispositions; a clean
  changed-path scan is not a clean whole-source scan.
- Bundled Workflow Specs, including `basic-loop`, can disappear from discovery
  after an upgrade changes the install directory despite their YAML remaining
  intact. The discovery fix is explicitly deferred beyond 0.5.14; this release
  contains no repair for it.
